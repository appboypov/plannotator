## Implementation Notes

- 1.1: Added the additive issue contract and API 1.3 in `packages/shared/review-api/{types,parse,version}.ts`. `parse.test.ts` proves trimming and invalid links (16 tests pass). Baseline: `ecba51d88cc09981d835a12af7a07d4c686964d4`.
- 1.2: `settings.ts`, `store.ts`, `service.ts` and `service.test.ts` implement issue persistence, refusal before mutation, keep/replace and old-state migration. HTTP proof through the real review service and upstream page server: 18 tests pass. An ended Review may update its issue without reopening its Round.
- 2.1: `records.ts` and new `records.test.ts` persist deliveries, enroll open reviewer events, preserve posted destinations and acknowledge posted notices (1 test, 11 assertions pass with disk reload). Relink mutates both record collections before awaiting one atomic replacement per changed file; existing separate remarks/notices files remain unchanged. `markPosted` optionally guards the captured destination against relink during HTTP. Delivery metadata stays out of page/listener payloads.
- 2.2: New `multica-poster.ts` builds the shared Markdown shape with Plannotator's reply tool and Approve/Close words. `multica-poster.test.ts` proves mention neutralization, line quoting, backtick fences, empty anchors, wordless deletions and notices (3 tests, 14 assertions pass).
- 2.3: `MulticaPoster` owns independent lanes, startup scan, 15-second abortable HTTP attempts, 1-second doubling retry capped at five minutes, per-attempt scratch/profile reads, safe logs and clean stop. Fake-server proof covers ordered comments, acknowledgement/reload, 503 then missing-id retries, token rotation, independent Reviews, pending restart, immediate relink and in-flight relink/abort (7 tests, 35 assertions pass). HTTP success whose reply is lost remains accepted at-least-once delivery, as ADR-0010 says.
